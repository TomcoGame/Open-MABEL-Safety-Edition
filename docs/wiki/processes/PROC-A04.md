# PROC-A04 — Document Configuration and Change Control

**Status:** Draft for technical review · **Revision:** 0.1 · **Application:** Open MABEL Safety Edition · **Process owner:** To assign

> This is an original project procedure framework. Applicability and clause-level coverage must be checked against licensed standards and a defined robot configuration.

## 1. Purpose and scope

Keep requirements, risk analyses, software, hardware and evidence mutually consistent across revisions. Applies to industrial mobile manipulation reference configurations and is tailored when other application profiles are selected.

## 2. Normative references to assess

ISO 12100 documentation; ISO 13849 validation records; applicable application standards. The [standards register](standards-register.csv) records editions and decisions; a listing here does not assert full applicability.

## 3. Entry criteria and inputs

Baseline configuration, change request, impacted artifacts. All inputs must identify configuration and revision.

## 4. Responsibilities

Configuration manager, technical owners, safety reviewer. The designated safety owner must confirm responsibilities and review independence before release.

## 5. Procedure

1. Assign document IDs and controlled revision states.
2. Link work products to configuration and release.
3. Submit proposed change with rationale.
4. Analyze hazards, requirements, interfaces, tests and instructions affected.
5. Obtain designated technical and safety approvals.
6. Update linked evidence and archive superseded versions.
7. Release only with traceable change disposition.

## 6. Decision gates and acceptance criteria

Every released change has traceable approval and impact review. Open assumptions and deviations must have named owners and disposition dates.

## 7. Outputs and controlled records

Approved baselines, change impact analysis, revision history, release manifest. Store outputs in the main repository with identifiers, revisions, approval status and links to related hazards, requirements, architecture and tests.

## 8. Traceability and change control

Any change to the robot configuration, intended use, environment, safety function or applicable standard triggers an impact review. Link changed process outputs to the [master process register](process-register.csv) and associated safety work products.

Use the [animated lifecycle map](../../assets/wiki/safety-lifecycle-animated.svg) and [static fallback](../../assets/wiki/safety-lifecycle-static.svg). Process-specific diagrams and worked examples will be reviewed before publication as engineering guidance.
